What this is

A child presses one button, speaks in English, Telugu, or a natural mix of both, and hears an immediate spoken response — no reading, no typing. It teaches the alphabet, numbers, colors, animals, vocabulary, songs, and short stories, in a warm, encouraging, age-appropriate way.

This is the Phase 1 prototype: proving the core voice experience first, before later phases add a learning curriculum, progress tracking, and a parent dashboard.

What you need

  • A computer (Mac/laptop) to run the app — it isn't hosted publicly yet, so it always runs from someone's machine for now.
  • Node.js installed on that machine.
  • A Gemini API key from Google AI Studio (free to create; enable the Live API for it).
  • To use it from a phone: the phone on the same Wi-Fi network as the computer running the app.

1On your Mac / laptop

This is the machine that actually runs the app; phones connect to it over the network.

git clone https://github.com/suryajogi/toddler-ai-voice-teacher.git
cd toddler-ai-voice-teacher

# Backend
cd backend
npm install
cp .env.example .env
# open .env and set GEMINI_API_KEY=<your key>
npm run dev

Leave that running, then in a second terminal:

cd toddler-ai-voice-teacher/frontend
npm install
npm run dev

Next.js prints a URL, typically http://localhost:3000. Open it in Chrome or Safari on that same Mac — press and hold the button, speak, and let go to hear the response.

2On an iPhone or Android phone

Read this before trying it: phones only allow a web page to use the microphone over a secure (https://) connection, or on literally localhost. Your phone isn't the computer running the app, so it can't use localhost — and a plain local-network address like http://192.168.1.83:3000 is treated as insecure, so the browser silently refuses microphone access even though the page loads fine. This isn't a bug in the app; it's how every phone browser works.

The fix: a quick HTTPS tunnel, using a free tool called cloudflared (no account needed). Do this on the Mac, with both npm run dev processes from step 1 already running:

brew install cloudflared

# Terminal 3 — tunnel the frontend (Next.js)
cloudflared tunnel --url http://localhost:3000

# Terminal 4 — tunnel the backend (the voice relay)
cloudflared tunnel --url http://localhost:8081

Each command prints a random https://something.trycloudflare.com URL — note both.

  1. Take the backend's tunnel URL, swap https:// for wss://, and add /voice — e.g. wss://random-words-1234.trycloudflare.com/voice.
  2. In frontend/.env.local (copy from .env.local.example if needed), set NEXT_PUBLIC_BACKEND_WS_URL to that wss://…/voice URL.
  3. Restart the frontend — it needs a restart to pick up the new env var.
  4. On the phone, open the frontend's tunnel URL in its browser.

The mic permission prompt should now appear normally — allow it, and the button works the same as on the Mac.

Both tunnel URLs are temporary and change every time you re-run the cloudflared commands, so you'll redo steps 1–3 each session. This is a testing workaround for the current local-only prototype — a real hosted deployment (planned for a later phase) would make this unnecessary.

🤖 Android shortcut

Chrome on Android has a flag, chrome://flags/#unsafely-treat-insecure-origin-as-secure, where you can allowlist your Mac's http://192.168.x.x:3000 address directly, skipping the tunnel entirely.

🍎 iPhone note

iOS Safari has no equivalent flag — the tunnel above is the only way to test the real microphone experience on an iPhone.

Troubleshooting

SymptomLikely cause
"GEMINI_API_KEY is not configured on the server" No real key in backend/.env yet, or the backend needs restarting after adding one.
Button never turns green / stuck on "Connecting…" Frontend can't reach the backend — check NEXT_PUBLIC_BACKEND_WS_URL matches where the backend is actually reachable.
No microphone prompt on a phone You're on a plain http:// address — see the tunnel steps above.
"Connection to voice server failed" right after looking ready Usually an invalid/expired API key — double-check it and that the Live API is enabled.
